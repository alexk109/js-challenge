# `verif/fuzz/`: the RTL/ISS lockstep fuzz

This harness runs the
RTL (`src/pio_chip.sv` + `src/pio_*.sv`) and the golden ISS (`iss.pio_iss.Chip`) on the same
stimulus, one core cycle at a time, and compares everything the spec makes observable. **It fixes
nothing.** A mismatch is a finding for the orchestrator to route to the ISS or RTL author.

| file | what |
|---|---|
| `gen.py` | the stimulus: seeded, and built from `docs/mvp-isa.md` / `docs/mvp-regmap.md` only. Instruction encoders, program generation, register setup, host traffic, `pin_in`, the guaranteed pin-conflict phase, and four fixed stimuli: `trivial()` (the selftest), `fifofill()` (FIFO storage), `pinloop()` (the pad model) and the generated run. |
| `lockstep.py` | the cocotb test (drives the DUT, steps the ISS, compares) and its command line. `--deep` compares the fields `state()` and `peek()` cannot show; `--pullup` adds a board to the stimulus. |
| `plant_iss.py` | the planted ISS bug for the selftest (a monkeypatch, imported into the simulator process). |
| `plant_iss_deep.py` | six more planted ISS bugs, one per deep field, all in one module: `FUZZ_DEEP_PLANT=fifo\|config\|div\|imem\|fdebug\|pinreq`. |
| `minimize.py` | shrinks a failing stimulus (ddmin over the host ops, then the cycle count). |
| `selftest.py` | `make fuzz-selftest`: proves the harness is not vacuous, shallow and deep. |
| `test_deep.py` | `make fuzz-deep-pytest`: the half of the harness that needs no simulator (pad model, unpacking, field list, stimuli, ISS `deep_state`). |
| `pullup_measure.py` | `make fuzz-pullup-measure`: is `--pullup` non-vacuous? Two runs of the same stimulus and the number of cycles in which the compared `in_vec` differs. |
| `conflict_measure.py` | `make fuzz-conflict-measure`: how often the plain generator makes the two engines contest one pin, i.e. how much of a campaign's coverage `conflict=N` is doing. No simulator. |
| `planted/` | copies of `src/pio_*.sv` with `-DFUZZ_PLANT_RTL<n>` bugs in them, regenerated by `planted/generate.py`. Never built into the chip. |
| `repros/` | every mismatch found, as a stimulus JSON plus a report. |
| `campaign.py` | many seeds in one go, with `metrics/fuzz.csv` (or `--csv`) rows. |
| `fuzz.mk` | the targets this directory adds to the top-level Makefile. |

## Using it

```sh
make fuzz SEED=3 CYCLES=10000        # one run; exit 1 on the first mismatch
make fuzz FUZZ_SIM=icarus             # the same run under Icarus
make fuzz-selftest                    # (a) clean, (b) planted RTL, (c) planted ISS, (d)-(h) the deep controls
make fuzz-repro REPRO=verif/fuzz/repros/<file>.json           # replay
make fuzz-repro REPRO=verif/fuzz/repros/<file>.json MINIMIZE=1  # shrink, then replay
make fuzz-deep-pytest                 # the simulator-free half (light slot)
make fuzz-pullup-measure SEED=1 CYCLES=300          # is --pullup non-vacuous? (medium slot)
make fuzz-conflict-measure SEEDS=1-20 CYCLES=10000 # pin-contest frequency, no simulator (light slot)

# Deep lockstep
make fuzz-deep SEED=3 CYCLES=20000                      # one run with every deep field
make fuzz-deep FUZZ_ARGS=--no-deep                      # ... only the 37 shallow signals
make fuzz-deep FUZZ_ARGS=--pullup                       # ... an un-driven uio pin reads 1
make fuzz-deep FUZZ_ARGS=--fifofill                     # ... the FIFO-storage stimulus
make fuzz-deep FUZZ_ARGS="--conflict 256"               # ... plus a guaranteed pin conflict
make fuzz-deep-campaign SEEDS=1-60 DEEP_CYCLES=20000    # the full run -> metrics/fuzz-deep.csv
make fuzz-plant5 SEEDS=1-20 DEEP_CYCLES=20000           # the same against planted copy 5 -> metrics/fuzz-plant5.csv

# both campaign targets write their repros to FUZZ_REPRO_DIR (default /tmp/fuzz-repros),
# not into the committed verif/fuzz/repros/: 20 planted repros are a sensitivity measurement, not
# a finding. A mismatch that *is* a finding: re-run with FUZZ_REPRO_DIR=verif/fuzz/repros.

python -m verif.fuzz.campaign --seeds 1-20 --cycles 10000     # many seeds + metrics/fuzz.csv
python -m verif.fuzz.lockstep --seed 3 --cycles 1000 --window 40   # one run, same as make fuzz
```

A mismatch report names the cycle, the field, both values, the last `FUZZ_WINDOW` (default 20)
cycles of both sides with every differing field marked, the host ops in the window, and the engine
setup that produced it. The repro beside it replays with
`python -m verif.fuzz.lockstep --repro <file>`: the seed fixes the pins, `ops` is the bus traffic,
`build` says which RTL build to replay against, and `mode` says how deeply it was compared (a deep
finding replays deep, so it cannot come back clean).

## What is compared, every cycle

Without `--deep` (37 fields, the original set):

* `pin_out`, `pin_oe`, `irq0`, `irq1` (chip outputs);
* `bus_rdata`, in a host read cycle (combinational in that cycle);
* every key of `Chip.state(e)` for both engines, against the RTL signal of the same name inside
  `g_eng[e].u_eng` (`pc ir x y osr isr osr_cnt isr_cnt delay_cnt stalled latch latch_pend
  latch_host forced tx_level rx_level`).

With `--deep` (157 fields; the default, since seeds 1-60 at 20k cycles ran clean) the five holes
`docs/mvp-verification-report.md` `### Known holes in the stimulus` lists are closed as well:

| field | RTL | ISS |
|---|---|---|
| `sm_enable` | `dut.sm_enable` | `peek(A_CTRL)` |
| `fdebug` | `dut.fdebug` | `peek(A_FDEBUG)` through `unpack_fdebug` |
| `inte0/1`, `intf0/1` | `dut.inte0` ... `dut.intf1` | `peek(A_IRQx_INTE/INTF)` through `unpack_irq` |
| `in_vec`, `in_pipe0` | `dut.in_vec`, `dut.in_pipe[0]` | `deep_state()["in_vec"]`, `sync[0]` |
| `eng{e}.clkdiv/execctrl/shiftctrl/pinctrl` | `u_eng.r_clkdiv` ... | `peek(A_SM_BASE + 6e + i)` |
| `eng{e}.div_cnt/div_acc/div_en` | `u_eng.u_div.cnt/acc/en` | `deep_state()[e]["div"]` |
| `eng{e}.tx[i]`, `eng{e}.rx[i]` | `u_eng.u_txf.mem[(rp+i)%4]` | `deep_state()[e]["tx"/"rx"]`, oldest first |
| `eng{e}.imem[k]` | `u_eng.imem[k]` | `deep_state()[e]["imem"]` |
| `eng{e}.os_we/os_dir/os_mask/os_data`, `ss_*` | `u_eng.os_*`, `u_eng.ss_*` | `deep_state()["req"]` |
| `res_level`, `res_dir` | `dut.lvl_n`, `dut.dir_n` | `deep_state()["res_level"/"res_dir"]` |

**The two per-engine registers this table does not list need no compare.** The engine register
block has six (`gen.py:46`: `SM_CLKDIV, SM_EXECCTRL, SM_SHIFTCTRL, SM_ADDR, SM_INSTR, SM_PINCTRL`)
and the `SM_ADDR` / `SM_INSTR` read-backs are absent above on purpose: the RTL defines them as
views of state that is already compared, `src/pio_engine.sv:762-763` being
`assign r_addr = {27'd0, pc};` and `assign r_instr = {16'd0, ir};`. `pc` and `ir` are two of the 37
shallow fields, so every cycle either engine's read-back differs, some already-compared field
differs with it.

The first eight rows are flop state and are read in the first half of the cycle, where the shallow
comparison reads its own. The last two are what the two sides *ask for in this cycle* and are read
in the second half, after the host access has been applied and the ISS has stepped: that is the
only moment at which the RTL's combinational `os_*`/`ss_*`/`lvl_n` and the ISS's recorded requests
are the same cycle's requests. A re-issued same-value side-set is invisible on `pin_out` and visible
in `eng{e}.ss_we`. It is also why plant 5 cannot be seen on 3 of 20 seeds at all without the
conflict phase (see `## The stimulus`): no comparison of any signal can see it in a run where the
two engines never write the same pin.

**"157 fields" counts slots, not independent comparisons.** In a cycle in which an engine's `out`
or `side` channel did not write, that channel's `dir`, `mask` and `data` are compared as `0 == 0`
(`lockstep.py` `DeepProbe.requests()`): the `we` bit is the whole request, and the other three are
combinational echoes that only mean something together with it -- `ss_dir` is `SIDE_PINDIR` itself
and `ss_mask` is the mask the side-set *would* have used, so comparing them against 0 would be
comparing configuration, which the `EXECCTRL` compare already does. So 12 of the 157 slots
(2 engines × 2 channels × 3) carry no information in a cycle where both channels are idle; in a
cycle where a channel does write, all four of its slots are live.

`Chip.deep_state()` (a small additive method in `iss/pio_iss.py`, next to `state()`) is what the
ISS side of this table reads; `state()` itself keeps exactly the keys `docs/mvp-interfaces.md`
`## ISS API` fixes, and the 314 ISS tests are unchanged by it.

The first mismatch stops the run.

## The pins and the pull-up

`pin_in` is the pad value, not the value the harness would like: a `uio` pin the chip drives
carries the chip's own driven level, whatever the outside world offers (docs/mvp-isa.md
`### The 18 protocol pins`: "`uio_in` follows the pad"), and only the rest carry the generated
value. `pin_vector(seed, cycle)` gives that generated value; it is a function of the seed and the
cycle alone, never of the op list, so shrinking a repro leaves the pins alone. A stimulus may also
hold pins low whatever the seed says (`Stimulus.ext_low`), which is how a board's pull-downs look.

`--pullup` adds the other half of that board: a `uio` pin the chip *releases* reads 1, which is
what an open-drain net with a pull-up resistor does and what the MVP's open-drain instructions
need. It cannot by itself make the two sides disagree -- it changes what the world offers, not
what the chip is asked to do -- and check (g) of `make fuzz-selftest` is the run that says so.

**How the mode's non-vacuity is measured.** Not by the coverage counter: `pad_value()` *forces* the
bit of every released pin and `Coverage.note()` counts the bit of that same `pin_in`, so
`uio_released_high / uio_released` is 100 % for any `--pullup` run, including one where the level
never reached the chip -- a number that cannot fail is not evidence. The measurement is
`make fuzz-pullup-measure` (`verif/fuzz/pullup_measure.py`): the same stimulus at the same seed,
once with `--pullup` and once without, both with `--pad-trace` (which records the per-cycle pad and
`in_vec`), and the number of cycles in which the *compared* `in_vec` differs. If the mode did
nothing to what the chip sees, the two traces are identical and that number is 0, so it can fail;
it also checks that every `in_vec` difference arrives exactly `T_IN` cycles after the pad itself
differed. The measurement is recorded below.

**What is still not measured.** No run yet breaks the *ISS* on the input-pipeline path (a plant that
drops the pad level the engines read), so the evidence is that the pull-up level demonstrably
reaches the compared field, not that a bug there would be caught. `gen.pinloop()` is the stimulus
that reads the pins back, so a wrong pad model is caught rather than assumed (`--pad-fault`).

## The stimulus

| stimulus | what it is for |
|---|---|
| `gen.gen(seed, cycles)` | the random run: coverage images, random images, host traffic, pins |
| `gen.gen(seed, cycles, conflict=N)` | the same, plus a phase of `N` cycles in which both engines divide by 1 and write the same pin with opposite data and opposite directions |
| `gen.fifofill()` | four words in each TX FIFO, a fifth the FIFO refuses, and a program that never drains them |
| `gen.pinloop()` | one engine drives pins, the other reads them back into X and Y |
| `gen.trivial()` | the fixed selftest stimulus |

The conflict phase exists because the cross-engine pin rule of docs/mvp-isa.md `### Pin writes`
("engine 1 wins over engine 0") is only reached when the two engines' clock dividers happen to line
up. `make fuzz-conflict-measure` measures how often that happens: on seeds 1-20 at 10k cycles with
the plain generator, **17 of 20** seeds ever make the two engines ask for the same pin register
with different values in the same cycle, and seeds **2, 7 and 12** never do -- in those three runs
*no* comparison of any signal can see plant 5, because the real RTL and the golden RTL behave
identically. (Measured; the counts per seed
run from 0 to 22.) `conflict=N` removes the luck and is what `metrics/fuzz-deep.csv` is measured
with. `conflict=0` is the default and produces exactly the stimulus `gen()` always produced, so
`metrics/fuzz.csv` and every committed repro stay reproducible.

## The planted bugs

| plant | the bug | what catches it |
|---|---|---|
| 1 | `jmp x--` does not write X-1 | `eng0.x` |
| 2 | `pc_update` ignores `WRAP_BOTTOM` | `eng0.pc` |
| 3 | side-set repeats while an instruction is stalled | `pin_out` |
| 4 | the autopull stall needs `osr_cnt > PULL_THRESH` | `eng0.stalled` |
| 5 | engine 0 wins a cross-engine pin conflict | `pin_oe` / `res_dir` |
| 6 | `irq0` follows only engine 0 | `irq0` |
| 7 | the FIFO push stores the word one slot along | `eng0.tx[0]`, and **nothing else** |

Plant 7 is the one that shows what `--deep` is for: on `gen.fifofill()` it is caught at cycle 76 by
the FIFO-contents compare (`eng0.tx[0]`, rtl `0x0` against iss `0x1000005a`), while the same build
with `--no-deep` matches all 37 shallow signals for the whole 120-cycle run, because a FIFO word
that nothing pops reaches nothing else. Both halves are checks (e) of `make fuzz-selftest`.

`verif/fuzz/plant_iss_deep.py` is the same idea on the model side: six patches, one per deep field,
each of which only that field can see.

**Which of these are shown to bite, and where.** `make fuzz-selftest` runs plants 1, 2, 5 and 7 and
the six ISS-side deep patches, and requires the mismatch to land in the field named above
(`-selftest.log`, 19/19). Plants 3, 4 and 6 are carried by `verif/fuzz/planted/` and buildable
(`make -C verif/fuzz PLANTED=1 PLANT=3`), but **no committed log exercises them**: the "what catches
it" column for those three rows is the field the plant breaks, not a measured outcome.

## The simulator

`verif/fuzz/Makefile` is the cocotb build, top level `pio_chip`, Verilator by default.

* **Lockstep visibility.** `docs/mvp-interfaces.md` asks for `--public-flat-rd`.
  **Verilator 5.050 has no such flag** (only `--public-flat-rw`), so the harness passes it when the
  installed Verilator knows it and otherwise relies on the `--public-flat-rw` that cocotb's own
  `Makefile.verilator` already passes; which one the build got is in every report
  (`visibility_flag`). Both make `dut.g_eng[e].u_eng.<name>` readable, which is what the harness
  needs. The deep comparison also reads the FIFO and IMEM arrays (`u_txf.mem[k]`, `u_eng.imem[k]`)
  and the divider inside `u_eng.u_div`, which the same flag makes visible.
* **Icarus works too**, with the same hierarchical reads and the same verdicts
  (`make fuzz FUZZ_SIM=icarus SEED=3 CYCLES=300`; it reports `seed 3 300 cycles match (157 fields,
  deep True)`), so the Verilator fallback was not needed. Icarus prints
  `vvp.tgt sorry: Case unique ... qualities are ignored`, which is harmless.

## Results

Runs of the deep lockstep, with the command or target that produced each one.

planted run does not write there. A planted run is a sensitivity record whose rows are `mismatch` by
construction, so `make fuzz-plant5` writes `metrics/fuzz-plant5.csv` by default (`PLANT5_CSV` in
`verif/fuzz/fuzz.mk`; `harness` = `lockstep-deep-plant5`). `make` exits non-zero for a planted
campaign **by design**: `campaign.py` returns 1 when any seed is not a `pass`, which for a planted
run is the result.
